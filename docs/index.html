TSLab на вашем VPS — одной командой

TSLab on your VPS — in a single command

Поставьте торговый сервер TSLab на собственный Linux-сервер и подключите его к своему аккаунту TSVerse. Без навыков системного администратора.

Put the TSLab trading server on your own Linux machine and connect it to your TSVerse account. No system administration skills required.

🐧 Linux / 🍏 macOS / 🪟 Windows 🐳 Docker 🔒 Вход через TSVerse (QR) ♻️ Данные сохраняются
🐧 Linux / 🍏 macOS / 🪟 Windows 🐳 Docker 🔒 TSVerse sign-in (QR) ♻️ Your data is kept

Что нужно

What you need

VPS или сервер

Любой Linux-сервер (Ubuntu/Debian и др.), 1–2 ГБ RAM. Подойдёт и домашний компьютер с Docker.

Доступ по SSH

Обычный пользователь с правами sudo (или root). Так заходят на VPS у любого хостинга.

Аккаунт TSVerse

Ваш аккаунт на tsverse.pro. Подтверждение входа — с телефона по QR.

Docker

Linux: скрипт ставит Docker сам. Windows: нужен Docker Desktop — скрипт попробует поставить его через winget, но после установки потребуется перезагрузка и запуск Docker Desktop.

A VPS or a server

Any Linux machine (Ubuntu/Debian and others), 1–2 GB RAM. A home computer with Docker works too.

SSH access

A regular user with sudo rights (or root) — the standard way to log into a VPS at any hosting provider.

A TSVerse account

Your account at tsverse.pro. The sign-in is confirmed from your phone via QR.

Docker

Linux: the script installs Docker for you. Windows: you need Docker Desktop — the script tries winget, but after that you have to reboot and start Docker Desktop yourself.

1 Установка одной командой

1 Install with one command

Зайдите на сервер по SSH и вставьте команду. Она проверит/поставит Docker, скачает TSLab, запустит его и доведёт до входа в TSVerse.

Log into the server over SSH and paste the command. It checks or installs Docker, downloads TSLab, starts it and walks you through the TSVerse sign-in.

Linux / macOS
Windows (PowerShell)
curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh | TSLAB_LANG=ru bash
curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh | bash
$env:TSLAB_LANG='ru'; irm https://nektodron.github.io/tslab-cloud/install.ps1 | iex
irm https://nektodron.github.io/tslab-cloud/install.ps1 | iex
🌐 Язык установщика. Установщик по умолчанию говорит по-английски и переключается на русский переменной TSLAB_LANG=ru (она уже есть в команде выше). Без неё язык берётся из локали сервера, но на не-UTF-8 терминале остаётся английским — кириллица там превращается в «кракозябры».
🌐 Installer language. The installer speaks English by default and switches to Russian with TSLAB_LANG=ru. Without the variable it follows the server locale, but stays English on a non-UTF-8 terminal, where Cyrillic would come out as mojibake.
🧭 Мастер установки. В терминале установщик спросит две вещи: папку для данных и регион TSVerse (global — tsverse.pro, ru — tsverse.ru, us — tsverse.us). Если TSLab уже стоит, папка существующего контейнера подставится сама — достаточно нажать Enter, данные и вход сохранятся. Ответы можно задать заранее переменными TSLAB_DATA_DIR и TSLAB_REGION — тогда вопросы не задаются (удобно для автоматической установки).
🧭 Setup wizard. On a terminal the installer asks two things: the data folder and the TSVerse region (global for tsverse.pro, ru for tsverse.ru, us for tsverse.us). If TSLab is already installed, the existing container's folder is offered by default — just press Enter and both the data and the sign-in are kept. Preset either answer with TSLAB_DATA_DIR and TSLAB_REGION to skip the questions (handy for unattended installs).
⚠️ Windows / PowerShell: используйте вкладку «Windows (PowerShell)» выше (команду irm … | iex). Команда curl … | bash в PowerShell не работает — там curl это Invoke-WebRequest, и вы получите ошибку «Не удается найти параметр fsSL».
⚠️ Windows / PowerShell: use the “Windows (PowerShell)” tab above (the irm … | iex command). curl … | bash does not work in PowerShell — there curl is an alias for Invoke-WebRequest and you get “A parameter cannot be found that matches parameter name 'fsSL'”.
Контейнер слушает только localhost — наружу ничего не открывается. Управлять сервером вы будете из своего обычного TSLab на компьютере: в нём выбираете удалённый сервер, и команды идут на VPS через TSVerse. Открывать веб-интерфейс сервера в интернет не нужно.
The container listens on localhost only — nothing is exposed to the internet. You drive the server from your usual TSLab on your computer: pick the remote server there and the commands travel to the VPS through TSVerse. There is no need to publish the server's web interface.

No code yet? It does not appear immediately — wait for the QR block in the logs (use -f so they keep streaming):
docker logs -f tslab
Missed the 5-minute window? The code simply rotates and the new one shows up in the same place.
После первого входа сервер запоминает вас. При перезапуске и обновлении повторно входить не нужно — сессия восстанавливается автоматически.
After the first sign-in the server remembers you. Restarts and updates do not need another sign-in — the session is restored automatically.

3 Управление через браузер

3 Manage it from the browser

Сервером удобнее всего управлять из веб-панели — её не нужно устанавливать, она открывается в любом браузере с любого устройства и общается с вашим VPS только через TSVerse (порты наружу открывать не надо).

The easiest way to run the server is the web console — nothing to install, it opens in any browser on any device and talks to your VPS only through TSVerse (no ports to expose).

  1. Откройте панель управления:
    🖥️ Открыть панель управления →
    Прямая ссылка: nektodron.github.io/tslab-cloud/app/
  2. Нажмите «Войти через Identity Server» и авторизуйтесь под тем же аккаунтом TSVerse, в который вошёл ваш сервер на шаге 2.
  3. Ваш сервер выберется автоматически. Если серверов несколько — выберите нужный в списке «Target» вверху страницы.
  4. Готово — управляйте агентами, скриптами, графиками и сделками. Все команды идут на ваш VPS через TSVerse.
  1. Open the web console:
    🖥️ Open the web console →
    Direct link: nektodron.github.io/tslab-cloud/app/
  2. Press “Sign in with Identity Server” and use the same TSVerse account your server signed into in step 2.
  3. Your server is picked automatically. With several servers, choose one in the “Target” selector at the top of the page.
  4. That's it — run agents, scripts, charts and trades. Every command travels to your VPS through TSVerse.
Панель ничего не хранит у себя: вход — это ваш токен TSVerse в браузере, а данные и команды идут напрямую на ваш сервер.
The console stores nothing of its own: the sign-in is your TSVerse token in the browser, and data and commands go straight to your server.

Housekeeping

Кроме веб-панели (шаг 3), сервером можно управлять и из вашего обычного TSLab на компьютере — выберите удалённый сервер, команды пойдут на VPS через TSVerse. Ниже — команды на самом сервере по SSH (логи, перезапуск, обновление):

Besides the web console (step 3) you can drive the server from your usual TSLab on your computer — pick the remote server and the commands travel to the VPS through TSVerse. Below are the commands you run on the server itself over SSH (logs, restart, update):

Команды на сервере (по SSH)

Commands on the server (over SSH)

docker logs -f tslab      # логи (и код входа в TSVerse)
docker restart tslab      # перезапуск (вход сохранится)
docker stop tslab         # остановить

docker stop tslab         # stop
docker rm -f tslab        # remove the container (data is kept)

Обновление до новой версии

Update to a newer version

Просто запустите установку ещё раз — подтянется свежий образ, а папка данных, регион и вход в TSVerse сохранятся (мастер сам предложит текущую папку):

Just run the installation again — it pulls the fresh image and keeps the data folder, the region and the TSVerse sign-in (the wizard offers the current folder by default):

curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh | TSLAB_LANG=ru bash
curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh | bash

Данные и безопасность

Data and security

  • Где данные. Всё (база, скрипты, настройки, сессия TSVerse) хранится на сервере в папке ~/.local/share/tslab, а не внутри контейнера — поэтому переживает перезапуск и обновление.
  • Бэкап. tar czf tslab-backup.tgz -C ~/.local/share/tslab .
  • Управление — через ваш локальный TSLab. В обычном TSLab на вашем компьютере выберите удалённый сервер — запросы пойдут на VPS через TSVerse. Веб-интерфейс самого сервера для этого не нужен: он слушает только 127.0.0.1:8088 и наружу не открыт.
  • Прямой доступ к WebUI сервера (необязательно). Если всё же хотите открыть его напрямую — пробросьте по SSH: ssh -L 8088:localhost:8088 user@your-vps, затем http://localhost:8088.
  • Вход. Подтверждение входа всегда происходит на вашей стороне (телефон/браузер) — пароль в скрипт и на сервер не передаётся.
  • Where the data lives. Everything (database, scripts, settings, TSVerse session) is stored on the server in ~/.local/share/tslab, not inside the container — so it survives restarts and updates.
  • Backup. tar czf tslab-backup.tgz -C ~/.local/share/tslab .
  • Management goes through your local TSLab. In your usual TSLab, pick the remote server — the requests travel to the VPS through TSVerse. The server's own web interface is not needed for that: it listens on 127.0.0.1:8088 only and is not exposed.
  • Direct access to the server WebUI (optional). If you do want it, forward it over SSH: ssh -L 8088:localhost:8088 user@your-vps, then open http://localhost:8088.
  • Sign-in. The confirmation always happens on your side (phone/browser) — no password is passed to the script or to the server.

Если что-то пошло не так

If something goes wrong

Docker не ставится / нет прав
Нужны права sudo или root. На большинстве VPS вы заходите под root либо под пользователем с sudo. Установить Docker вручную: docs.docker.com/engine/install, затем запустите команду установки снова.
Docker will not install / not enough rights
You need sudo or root. On most VPS boxes you log in as root or as a user with sudo. To install Docker by hand: docs.docker.com/engine/install, then run the install command again.
Порт 8088 уже занят
Запустите с другим портом:
TSLAB_PORT=8090 bash -c "$(curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh)"
Port 8088 is already taken
Start it on another port:
TSLAB_PORT=8090 bash -c "$(curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh)"
Ошибка «invalid option name pipefail» или «curl: Failed writing body»
Так выглядит скрипт, скачанный с переносами строк Windows (CRLF): bash читает set -o pipefail␍ и падает, а вслед за ним обрывается и curl. Файл на сайте отдаётся с LF, поэтому сначала просто повторите команду. Если ошибка осталась — вы, скорее всего, запускаете локальную копию: почистите её переносы строк (sed -i 's/\r$//' install.sh) или скачайте заново.
Error “invalid option name pipefail” or “curl: Failed writing body”
That is what a script downloaded with Windows line endings (CRLF) looks like: bash reads set -o pipefail␍ and dies, and curl then fails to finish writing into the broken pipe. The file on this site is served with LF, so just run the command again. If it persists you are most likely running a local copy: strip its line endings (sed -i 's/\r$//' install.sh) or download it anew.
Как сменить папку данных или регион TSVerse позже
Запустите установку ещё раз: мастер покажет текущую папку и текущий регион — ответьте n и выберите другие. Разово можно и без вопросов:
curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh | TSLAB_DATA_DIR=/srv/tslab TSLAB_REGION=ru bash
Регион хранится в файле <папка данных>/launchSettings.json. Учтите: смена региона или папки — это другой аккаунтный контур, инстанс попросит новый вход в TSVerse.
How to change the data folder or the TSVerse region later
Run the installation again: the wizard shows the current folder and region — answer n and pick different ones. Or skip the questions entirely:
curl -fsSL https://nektodron.github.io/tslab-cloud/install.sh | TSLAB_DATA_DIR=/srv/tslab TSLAB_REGION=ru bash
The region lives in <data folder>/launchSettings.json. Note that changing the region or the folder means a different account space — the instance will ask for a new TSVerse sign-in.
Вместо русского текста «кракозябры»
Терминал не в UTF-8. Либо переключите его на UTF-8 (export LANG=ru_RU.UTF-8), либо запустите установщик по-английски — уберите TSLAB_LANG=ru или задайте TSLAB_LANG=en. На Windows то же самое: $env:TSLAB_LANG='en' перед командой.
Russian text shows up as mojibake
The terminal is not UTF-8. Either switch it to UTF-8 (export LANG=ru_RU.UTF-8) or run the installer in English — drop TSLAB_LANG=ru or set TSLAB_LANG=en. Same on Windows: $env:TSLAB_LANG='en' before the command.
Windows: ошибка «Не удается найти параметр fsSL» (PowerShell)
Вы вставили Linux-команду в PowerShell. Возьмите команду из вкладки Windows (PowerShell):
irm https://nektodron.github.io/tslab-cloud/install.ps1 | iex
Windows: “A parameter cannot be found that matches parameter name 'fsSL'”
You pasted the Linux command into PowerShell. Take the command from the Windows (PowerShell) tab instead:
irm https://nektodron.github.io/tslab-cloud/install.ps1 | iex
Не увидел код входа в TSVerse
Код появляется через ~30–60 секунд после старта (сервер сперва пытается восстановить прошлую сессию). Смотрите логи с -f и дождитесь блока с QR: docker logs -f tslab. Если вход уже был выполнен ранее, кода не будет — сессия восстановлена автоматически.
I never saw the TSVerse sign-in code
The code shows up ~30–60 seconds after the start (the server first tries to restore the previous session). Watch the logs with -f and wait for the QR block: docker logs -f tslab. If you signed in earlier there will be no code at all — the session was restored automatically.
Как полностью переустановить «с нуля»
Удалите контейнер и данные, затем установите заново:
docker rm -f tslab && rm -rf ~/.local/share/tslab
How to reinstall from scratch
Remove the container and the data, then install again:
docker rm -f tslab && rm -rf ~/.local/share/tslab
Файлы в папке данных принадлежат root
Контейнер работает от root, поэтому файлы в ~/.local/share/tslab создаются от root. На своём VPS это нормально. Управлять/удалять их можно через sudo.
Files in the data directory are owned by root
The container runs as root, so files in ~/.local/share/tslab are created by root. On your own VPS that is fine — manage or delete them with sudo.
